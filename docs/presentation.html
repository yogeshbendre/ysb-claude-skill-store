Why this exists

Skills are just markdown — but sharing them isn't

  • A Claude Code skill is a prompt file — drop it in .claude/commands/ and it becomes a slash command.
  • Every team reinvents the same ones — code review, formatting, changelogs, headers...
  • There was no shared, browsable place to find and install one in seconds.
  • The fix: one repo of skills, one gallery site to browse them, one command to install.
Repo structure

Everything lives in one repo

│   ├── index.html
│   ├── assets/  (style.css, app.js)
│   └── skills-index.json    # auto-generated, don't hand-edit
├── .github/workflows/       # CI regenerates the index on push
├── CONTRIBUTING.md           # the rules for adding a skill
└── README.md
Anatomy of a skill

Every skill folder has the same three files

skills/<your-skill-id>/
├── skill.json   # metadata: id, name, description,
│               # version, author, domain, tags, license, publish
├── skill.md     # the actual prompt Claude runs for /<id>
└── README.md   # usage docs and examples
  • skill.json is what powers search, filtering, and the install link — nothing here is hand-maintained in the gallery.
How it's wired together

  • No manual rebuild step. Push to skills/ and the index regenerates automatically.
  • "publish": false" in skill.json keeps a draft skill out of the index entirely.

Light/dark theme, mobile-friendly

  • Theme toggle, top right of the header — remembers your choice, respects OS preference on first visit.
  • Filter panel becomes a slide-in drawer on mobile via a "Filters" button next to search.
  • Every card links to the raw skill.md and the source folder on GitHub, in addition to the one-line install.
Using a skill

Download & install in under a minute

  • Open the gallery at yogeshbendre.github.io/ysb-claude-skill-store
  • Search or filter to find the skill you want
  • Click "Copy install" on its card
  • Paste into your project's terminal — it curls the skill.md into .claude/commands/
  • Run /<skill-id> inside Claude Code — done
Contributing a skill

Publishing your own skill

  • Clone or fork the repo
  • Create skills/<your-skill-id>/
  • Add skill.json, skill.md, README.md — see CONTRIBUTING.md for the schema
  • Add a row to the skills table in the root README.md
  • Push, or open a pull request — CI regenerates the gallery automatically
Shortcut

Or let a skill do it for you

  • /skill-store-push <path> point it at any existing command file or skill folder, from any repo.
  • It drafts everything — skill.json, skill.md, README.md — and asks you directly about anything ambiguous (domain, author...).
  • It only commits and pushes after you explicitly say yes.
Recap

One repo. One gallery. One line to install.

  • Skills live in skills/<id>/ as skill.json + skill.md + README.md
  • The gallery builds itself from those files via GitHub Actions
  • Anyone can install a skill in one command — and contribute one back just as easily
